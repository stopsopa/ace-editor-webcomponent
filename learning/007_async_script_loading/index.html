Lesson 007: Async Script Loading

What You'll Learn

A web component often needs an external library. The library should be loaded only when the first component appears, and only once, no matter how many components are on the page. This lesson shows the same pattern in two variants:

  • Variant 1: ES module - the dependency is an ES module, loaded with dynamic import()
  • Variant 2: window global - the dependency is a classic script which puts a function on window, loaded with a <script> tag and its onload / onerror events. This is the variant used later for Ace Editor.

The Pattern

let promise = null;

// NOT an async function: nothing is awaited between the check and the assignment
function loadOnce() {
    if (!promise) {
        promise = new Promise((resolve, reject) => {
            const script = document.createElement('script');
            script.src = url;
            script.onload = () => resolve(window.theLibrary);
            script.onerror = () => reject(new Error('Failed to load ' + url));
            document.head.appendChild(script);
        });
    }
    return promise;
}

Key Takeaways

  • Cache the promise, not the result - components which arrive while loading wait for it
  • Store the promise in the same synchronous step in which you checked that it is missing. If anything is awaited in between, all components connected in that time start their own loading
  • Components declared in html before the script loads, and components added later, use the same path
